EvOrderBench

When do sampled frames establish event order?

A few sampled frames can show that two actions happened without showing which came first. EvOrderBench tests whether a model states an order only when its frames establish it, and withholds otherwise.

Abstract

Vision-language models (VLMs) are often asked which of two actions in a video happened first, given only a few sampled frames. Such frames can show that both actions occurred without showing which came first, so a reliable model should state an order only when the frames establish it. Forced-choice temporal benchmarks treat every input as answerable and reward lucky guesses, while answerability benchmarks do not separate frames that miss an action from frames that show both actions but not their order.

We introduce EvOrderBench, a real-video benchmark of 579 event families. Each family fixes an episode and a question and varies only the frames: of two four-frame inputs, only one establishes the order, and two six-frame inputs extend the other one with either the frames that resolve the order or frames that do not. Every input is labeled for whether its frames establish each action and their order.

Across sixteen open-weight configurations and three closed-source references, the best open models order nearly as accurately as the references when the frames establish the order, but withhold correctly on at most 83% of the inputs where they do not, against at least 90% for every reference; forced-choice accuracy cannot reveal this gap. Open models withhold mainly when the frames show neither action; once the frames show one or both, most of them commit to an order. Thinking narrows the gap, even when it is switched on within a single checkpoint, mainly by separating sufficient from insufficient evidence rather than by making models more cautious overall. Accurate ordering thus does not imply knowing when the frames fall short, and benchmarks should reward withholding alongside ordering.

Why it matters

A confident wrong order is worse than “I can’t tell.”

Every model below was told, in so many words, to answer UNCLEAR when the frames do not establish the order. Most open instruction-tuned models answer anyway. The orders they name are informed guesses: they match what happened more often than chance, but far from reliably, and a forced-choice benchmark would count every match as temporal understanding.

Video assistants recap events

Summaries of a home-camera clip, a meeting or a lab recording are built from a handful of frames. An order the frames never showed reads exactly like one they did, and the user has no way to tell the difference.

Agents verify step order

Robots and computer-use agents verify progress from sparse observations: was the gripper opened before the object was released, was the form saved before the window closed. Treating an unresolved order as resolved means acting on a step that may not have happened yet.

Scores shouldn’t reward guessing

On a forced-choice benchmark a lucky guess scores the same as an observation. Here, how well a model orders tells you little about whether it knows when it cannot: . EvOrderBench scores both, on the same episodes.

Design

The benchmark

Four observation sets per family

H
Four frames that include the intermediate frames resolving the order.
L
Four frames that omit them, with the same first and last frame as H.
K
L plus the two critical frames that distinguish H from L.
P
L plus two peripheral frames that are not meant to resolve the order.

H vs. L and K vs. P compare inputs with the same number of frames, so differences cannot be attributed to input length. Joint metrics require a model to order H and withhold on L.

Three ways evidence falls short

U0
The frames establish neither action.
U1
The frames establish one action; the other is missing.
U2
The frames establish both actions, but not which came first.

Every input carries occurrence labels for both actions and an order label, so a missing action can be told apart from an unresolved order.

The exact prompt every model receives “Choose A or B only when the supplied images establish the order of both specified actions. Otherwise choose UNCLEAR.” Show the full prompt 

          
Each input is asked twice, with the answer letters A and B exchanged between the two actions, so a model cannot score by preferring one letter.

Takeaways

          
Findings

        

        
    
          
  1. 01
    Ordering and withholding diverge
    When the frames establish the order, the best open models nearly match the closed references. Yet only two open configurations withhold correctly on more than 70% of insufficient inputs, against at least 90% for every reference. A forced-choice score cannot see this gap.
    2. 
          
  2. 02
    What is missing matters
    Open models withhold mainly when the frames show neither action. Once the frames show at least one action, most commit to an order, whether the second action or only the order is missing.
    3. 
          
  3. 03
    Thinking narrows the gap
    Also when it is switched on within one checkpoint, mainly by separating sufficient from insufficient evidence rather than by making models more cautious overall. Even so, the best open configuration answers all eight queries of a family correctly for only two thirds of the families.

Use EvOrderBench

          
Evaluate your model in three steps.

          
Any model behind an OpenAI-compatible endpoint, hosted or local (for example vLLM). The scripts need only Python 3.8+.

          
 Dataset on Hugging Face Code on GitHub

        

        
    
          
  1. 
            01
            
    Get the data
    
            
    579 families, 2,316 inputs, 4,632 queries with prompts, frames and reference answers. Clone the code from GitHub, which includes the answers of all 19 configurations, and download the data into it.
    
            
    hf download \
  xiaoqinfeng/EvOrderBench \
  --repo-type dataset \
  --local-dir datasets
    
          
    2. 
          
  2. 
            02
            
    Run your model
    
            
    Frames go in their listed order, followed by the prompt. Add --thinking for models that reason first. Runs resume if interrupted.
    
            
    python code/run_openai_api.py \
  --model MODEL \
  --base-url http://localhost:8000/v1 \
  --out outputs/MODEL
    
          
    3. 
          
  3. 
            03
            
    Score it
    
            
    Prints every column of the leaderboard. --ci adds 95% intervals from a bootstrap over the 558 recording groups.
    
            
    python code/evaluate.py --ci \
  --predictions \
  outputs/MODEL/predictions.csv
    
          
    4. 
        

        
Reporting results? Give Ord. and Insuf. together, or a joint metric such as Pair HL. Either one alone can be maximised by always ordering or always withholding: the Always A and Always UNCLEAR rows of the leaderboard do exactly that.
